ReplayFoundry Visual Semantic Output Normalization Policy 1.0

Purpose

This policy permits the Qwen3-VL host to canonicalize two representational
collections after strict provider-output validation. It does not permit
semantic repair.

Validation baseline

- The generated text must be valid bounded UTF-8 containing exactly one bare
  JSON object.
- Duplicate JSON properties, non-finite values, markdown wrappers, and
  prohibited chain-of-thought properties or content are rejected.
- The observation must contain the exact required properties, identities,
  enums, evidence, timestamps, and bounded text.
- Raw array count limits apply before exact duplicate removal.
- Limitation strings and uncertainty descriptions use the existing validated
  trimming baseline before length validation and canonicalization.
- Other semantic text is never trimmed or rewritten by this policy.

Permitted normalization: LimitationsCanonicalized

- Remove only exact ordinal duplicate limitation strings.
- Sort remaining limitation strings using .NET-compatible ordinal UTF-16 code
  unit order.
- Preserve case variants, punctuation variants, and every surviving string
  byte-for-byte after the validated trimming baseline.

Permitted normalization: UncertaintiesCanonicalized

- Remove only exact duplicate (code, description) pairs.
- Sort remaining entries by the declared uncertainty-code order and then by
  .NET-compatible ordinal UTF-16 description order.
- Preserve distinct descriptions sharing one code.
- Never change a code or rewrite a description.

Prohibited normalization

The host must not add a missing property, delete an unknown property, repair
malformed JSON, extract JSON from markdown, change an enum or identity, alter
visible state, certainty, rationale, or worth-reviewing values, change or
clamp an evidence timestamp, sort or deduplicate evidence intervals, truncate
text, or add or remove any semantically distinct limitation or uncertainty.

Audit

Every changed case records exact pre-normalization and canonical hashes,
counts, duplicate counts, order-change flags, ordered normalization kinds,
this policy identity, a zero-offset normalization timestamp, and
semanticTextChanged=false. An unchanged case records a null normalization
audit.
